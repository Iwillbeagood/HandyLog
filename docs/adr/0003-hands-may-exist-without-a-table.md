# 핸드는 테이블 없이도 존재할 수 있다 (Text record)

지금까지 모든 핸드는 하나의 `PokerTable`에 속했다(`HandRecord.tableId` non-null, FK CASCADE). 테이블을 먼저 만들어야 핸드를 남길 수 있어, "방금 그 핸드만 빨리" 남기려는 사용자에게 진입 비용이 컸다.

## 결정 (2026-10)

`HandRecord.tableId`를 **nullable**로 바꾸고, 홈의 [새로 만들기] → [텍스트 기록]으로 테이블 없이 핸드를 기록할 수 있게 한다.

- 테이블 없는 핸드의 좌석은 `1..인원`, 히어로는 1번 좌석으로 두고, 버튼은 히어로 포지션에서 역산한다(포지션은 좌석에서 파생 — ADR-0001 유지).
- 블라인드를 생략하면 `QuickHandConfig.BB_UNIT_BLINDS`(0.5/1)로 기록해 팟·스택 계산은 그대로 동작한다.
- FK는 유지한다. `tableId`가 null이면 FK 검사 대상이 아니며, 테이블 삭제 CASCADE는 테이블에 속한 핸드에만 적용된다.
- 무료 한도는 테이블 없는 핸드 전체를 하나의 묶음으로 보고 `MAX_FREE_HANDS_PER_TABLE`을 적용한다.

## 근거

- 숨은 테이블을 자동 생성하는 대안은 스키마 변경이 없지만, 사용자가 만들지 않은 테이블이 목록·한도·통계에 섞인다. 도메인을 사실대로 표현하는 쪽을 택했다.

## 대가 / 주의

- **앱이 배포된 이후 첫 스키마 변경**이다. ADR-0002의 "배포 전이라 마이그레이션 없이 직접 변경" 전제는 더 이상 유효하지 않다 — 이번부터 스키마 변경은 실제 `Migration`(`local/database/.../migration/Migrations.kt`)을 작성한다. `fallbackToDestructiveMigration`은 안전망으로만 남아 있으며, 마이그레이션이 누락되면 사용자 데이터가 삭제된다.
- 핸드→테이블을 따라가는 코드(`HandWithTable.table`, 핸드 상세의 테이블 이동, 플레이어 마킹의 테이블 좌석 갱신)는 null을 처리해야 한다.
